# RK2020 NES launch validation (2026-10-26)

## Scope

Validate the representative NES route on the live RK2020 without rewriting the
SD image:

- ROM: `/mnt/plumos-user/roms/FC/Akumajou Densetsu.nes`
- profile: `retroarch:quicknes`
- core: `/mnt/plumos/cores/quicknes_libretro.so`
- target: stock Linux 4.4.189 RK2020 runtime

## Failures and fixes

The first launch stopped in the audio preflight. The stock kernel exposes the
RK817 ALSA card ID as `rockchiprk817co`, while the managed audio layer only
accepted `rockchiprk817`. Commit `4f16de4` accepts the stock alias in both the
shell route selector and the ALSA hotplug plugin.

After the audio route passed, the stock dynamic loader reported missing
`libdl.so.2`, followed by `librt.so.1`. The stock `/usr/lib/libmali.so` was
copied read-only for dependency inspection and declares these legacy glibc
dependencies:

```text
libdl.so.2
libpthread.so.0
librt.so.1
libdrm.so.2
libm.so.6
libstdc++.so.6
libgcc_s.so.1
libc.so.6
```

Debian bookworm resolves the old split-library symbols from libc during the
build and therefore did not discover all target-side compatibility DSOs.
Commits `a6b24e7` and `ac43090` make the RetroArch component explicitly bundle
and verify `libdl.so.2`, `libpthread.so.0`, and `librt.so.1`.

## Device result

The frontend was stopped through its managed stop helper before the test. The
NES route then produced these live processes:

```text
/mnt/plumos/bin/plumos-text-ui launch nes FC/Akumajou Densetsu.nes --profile retroarch:quicknes --execute --no-scan
/mnt/plumos/bin/plumos-retroarch-launch --system nes --core /mnt/plumos/cores/quicknes_libretro.so ...
/mnt/plumos/bin/retroarch ... -L /mnt/plumos/cores/quicknes_libretro.so /mnt/plumos-user/roms/FC/Akumajou Densetsu.nes
```

ALSA playback was owned by the RetroArch PID and remained `RUNNING`. Over one
second, `hw_ptr` advanced from `238408` to `286616`, confirming active audio
playback rather than only a successful open.

The test process group was terminated after evidence collection. No emulator
process remained, and the frontend restarted successfully as PID 17245.

## Remaining physical gates

The automated test proves program startup, QuickNES core loading, continued
execution, active audio, cleanup, and frontend restoration. The following must
still be confirmed by direct play on the device:

- rendered game image and orientation;
- D-pad and face-button mapping;
- in-game menu and clean return to the frontend;
- save-state and persistent save behavior.

The launch log also contains non-fatal warnings for the absent XKB data path,
ALSA control/sequence devices, and the optional `plumos-safe-hotkeyd`. They did
not prevent the NES process or audio stream from running, but exit/menu behavior
is intentionally left as a separate hardware gate.
