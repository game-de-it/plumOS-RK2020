# RK2020 plumOS host build validation

Date: 2026-10-25

Source ref: `2e0d921`

Scope: host build, package audit, filesystem readback, and first-boot storage
simulation. This is not RK2020 physical acceptance.

## Build environment and recovery

The macOS host ran out of free space during the first build attempt and the
Docker backend stopped responding. After host space was recovered, Docker was
restarted and reported version `29.6.2` with the `overlayfs` storage driver.
The completed build left approximately 19 GiB free on the Data volume.

No removable physical disk was visible to `diskutil list external physical`,
so this validation did not flash media. The stock RK2020 at
`root@192.168.10.107` was used only for the separately recorded read-only
inventory; its stock SD was not modified.

## Integrated RK2020 substrate

- the checksum-registered 16 MiB stock Rockchip prefix;
- stock Linux 4.4.189 KERNEL, active RK3326 DTB, initramfs, module tree, and
  firmware tree as one matched ABI set;
- stock Mali userspace driver with `libEGL`, `libGLES`, and `libgbm` SONAMEs
  provided by `/usr/lib/libmali.so`;
- stock `8821cu` for USB IDs `0bda:c811` and `0bda:c820`, with matching
  `4.4.189 SMP mod_unload aarch64` vermagic;
- RK817 audio, backlight, battery/charger, power key, physical input map, panel
  rotation, and bounded USB/Wi-Fi recovery policy;
- plumOS frontend, RetroArch, 110 libretro cores, PicoArch, OpenBOR,
  PCSX-ReARMed, DraStic, PPSSPP, Mupen64Plus, Pyxel, NextCommander, music,
  network services, and PortMaster.

The native app layer is rejected if it contains Mesa/GLVND provider libraries
that would shadow stock `libmali`. DraStic's required armhf vendor libraries
remain isolated under its private 32-bit runtime. PPSSPP and Mupen64Plus retain
their EGL/GLES ABI requirements and resolve them from System on RK2020.

## Required physical acceptance

Use a separate test SD and preserve the stock recovery card. The following are
still independent gates and must not be inferred from the host build:

1. cold boot, boot splash, panel orientation, brightness, and frontend;
2. D-pad, both analog axes, ABXY, shoulders, Start/Select, and Function menu;
3. speaker, headphone detection, volume range, and audio after resume;
4. USB `0bda:c811` Wi-Fi association, DHCP, reconnect, remove/reinsert, and
   actual updater/network-service paths;
5. representative ROM launch and return for libretro, PicoArch, each
   standalone emulator, Pyxel, and PortMaster;
6. save/state persistence and USER partition growth across a reboot;
7. in-game Reboot, Shutdown, and Sleep/resume as three separate tests,
   including charger-connected and charger-disconnected shutdown behavior;
8. final SD readback hash or filesystem check after physical testing.
